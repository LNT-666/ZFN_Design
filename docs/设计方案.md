# ZFN_Design：从 DNA 序列到锌指核酸酶设计的可审计流水线

---

## 0. 一页看懂

**它做什么。** 输入一段 DNA 序列（基因、启动子、外显子……），输出：

1. 所有"形状上像 ZFN 结合位点"的位置（左半位点 + spacer + 右半位点，半位点 9 bp 或 18 bp）；
2. 每个位置按**指头库证据强度**判定的可设计性（能设计 / 只能用未验证指头 / 数据缺失）；
3. 每个可设计位置上的 3–10 个候选 ZFN，含**氨基酸序列**、**逐项可审计的分数**、**in silico 脱靶清单**；
4. 单文件 HTML 报告 + JSON + TSV，以及 NLS–ZF–VP64 等融合构型的草稿序列；
5. 一张"你最该补哪些三联体指头"的采购清单——这是本工具最实用、也最少见的输出。

**它不做什么（请先读这一段）。**

- 它**不预测活性**。分数只表示"按公开设计规则看起来更像好位点"，与实测亲和力、切割效率**没有定量关系**；
- 它**不替代湿实验**。任何设计在合成之前都必须经过 T7E1 或 amplicon 深度测序验证；
- 它**不做全基因组脱靶搜索**（需要 Bowtie/BLAST 级别的索引与参考基因组；本工具只在用户提供的序列集合里搜，见 §6.6）；
- 它**不假装库是完整的**。随包库（Persikov 2015 B1H，1,027 条）覆盖 64/64 个三联体，但原始数据只测了阵列中的 F2/F3 两个位置；缺位靠"同三联体跨位置"兜底，并在报告里显式标注「非本位上下文、行为未验证」。这一层区分见 §7.2。

> **最重要的限制（关于阵列长度）。** 三指 ZFP 只读取 **9 bp**，单独作为单体在人类基因组中**并不唯一**。若需要基因组单拷贝结合，应把它作为 ZFN 配对的一半（本工具默认成对输出），或扩展为**六指阵列**（读 18 bp）并重新验证。本文件不保证活性或特异性，所有设计均需实验验证。三指与六指的取舍见 §4.5。


**为什么不能"一键出高活性 ZFN"。** 这是本方案最重要的前提，展开在 §3。

## 2. 术语与记号（速查，完整版见 `docs/术语表.md`）

| 记号 | 含义 |
|---|---|
| ZF | zinc finger，锌指；本文默认指 Cys2His2（C2H2）型 |
| ZFN | zinc finger nuclease，锌指核酸酶 = ZF 阵列 + FokI 催化域 |
| 半位点 half-site | 一个 ZF 阵列（通常 3 指）识别的 9 bp |
| spacer | 两个半位点之间不被蛋白接触的碱基，经典 ZFN 为 5–7 bp（最常用 6） |
| 识别螺旋 | 指头中插入 DNA 大沟的 α 螺旋，7 个关键残基位于 −1, 1, 2, 3, 4, 5, 6 |
| 三联体 triplet | 一个指头识别的 3 bp；本文写作 5'→3' 的**编码链**方向 |
| 指位 F1/F2/F3 | 阵列中的第 1/2/3 个指头，**从 N 端数起** |
| 证据层级 Tier1/2/3 | 见 §6.3；这是本方案区分"能用"与"看起来能用"的唯一标准 |

**方向约定（全项目最容易出错的地方，务必对齐）：**

1. 半位点 `GCGTGGGCG` 在编码链上写。三个指头 **N→C 的顺序对应 DNA 的 3'→5'**，即 N 端指头读半位点**最右**的三联体。因此：

   ```text
   编码链  5'-G C G | T G G | G C G-3'
   指头顺序          F3      F2      F1     （F1 在最前，即 N 端）
   ```

2. 右侧半位点在双链上以**反向互补**出现。存储时永远存"编码链写法"，比较时再取反向互补——代码里 `TargetSite.site_seq` 恒等于 `left_half + spacer + revcomp(right_half)`，这条不变量有单元测试守着。

## 3. 现状：为什么没有"万能 ZFN 设计软件"

### 3.1 工具盘点结论（2026-11-13 实测）

一句话：**不存在"输入任意 DNA 就得到经验证高活性 ZFP"的公开软件。** 现有资源分成四类：

| 类别 | 代表 | 能给什么 | 不能给什么 |
|---|---|---|---|
| 在线靶点/脱靶搜索 | **ZFN-Site**（`epd.expasy.org/tagger/`） | 在既有基因组里找"像 ZFN 位点"的位置 | 不设计指头；只用 hg38/mm10 等较旧基因组；页面提示维护中 |
| 在线特异性预测 | **ZiF-Predict IHBE**、**Princeton ZF PWM Predictor** | 给定指头序列 → 预测其 3 bp 特异性 | 只能预测，不生成；ZiF-Predict 仅 9 bp/3 指、2010 年能量模型、无脱靶分析 |
| 公开代码 | **ZFNsearch**（Bash，本质 `grep -E`）、**DeepZF**（只预测）、**sirnaforge ZFN 模块**（作者自标 EXPERIMENTAL）、**Tsinghua iGEM 2026 dry-lab**（项目专用） | 零散能力 | 没有一个能构成"输入序列→可合成阵列→打分→报告"的闭环；sirnaforge 自述存在半位点方向、FokI seed 权重、worst/best 命名反转等未修复缺陷 |
| 闭源/受限 | **ZFDesign**（Ichikawa 2023，层级 Transformer，约 490 亿蛋白–DNA 互作训练） | 目前最强的计算设计 | 学术 MTA、代码不公开、无公共服务器；Sangamo 平台同理 |

已明确下线、**不要**在方案里当可用资源引用的：Zinc Finger Tools、ZiFiT/ZiFOpT、CoDA、OPEN、ZFNGenome、ZiFDB v1/v2、EENdb、PROGNOS、ZFP-Finder、ZFPsearch。

### 3.2 三个硬约束（决定本方案的形态）

**(a) 模块化组装失败率高。** Ramirez 等 2008 年报道，模块化组装得到的锌指阵列中有相当大比例（超过一半）在细胞实验中活性很低甚至检测不到<sup>[1]</sup>。根本原因是**相邻指头的界面会改变各自的特异性**——单个指头"应该"识别 XYZ，装进阵列后未必还是。这是本方案**不敢**把"三联体查表拼起来"称作"设计"的原因。

**(b) 结合 ≠ 切割。** in silico 找到的"相似位点"只是**序列相似**；染色质可及性、甲基化、局部结构、FokI 二聚化几何都决定它是否真的被切。所以本工具输出的是 `burden`（负担/风险），不是"切割概率"。

**(c) 数据而非算法才是瓶颈。** 真正的 B1H 特异性数据（Persikov 2015）覆盖全部 64 个 3 bp 靶点、超过 16 万个 domain–DNA 互作<sup>[2]</sup>，但它是**需申请**的数据集，且只测了阵列中的两个位置。所以本方案的架构是"**导入器 + 明确缺口 + 缺口兜底但标注**"，而不是"内置一个假装完整的库"。

### 3.3 本方案的定位

> 做一个**诚实、可审计、可扩展的工程骨架**：把 ZFN 设计的每个环节显式化、把每个判断的依据标出来、把数据缺口大声喊出来；在拿到好数据（B1H 或 ZFDesign/MTA 结果）时能无缝升级，在没拿到时明确告诉你"这一步做不了"，而不是编一个看起来很像的答案。

## 4. 生物学基础（只写会影响实现的那些）

### 4.1 C2H2 指头与识别螺旋

一个 C2H2 指头约 30 aa，折叠成 ββα，其中 α 螺旋（识别螺旋）插入 DNA 大沟。Persikov 2015 的关键结论：**决定特异性的主要是识别螺旋的 4 个位置（−1, 2, 3, 6）**，称为 **core sequence**；位置 1 和 5 的熵显著更高（对特异性贡献小）<sup>[2]</sup>。

本方案的 `FingerRecord` 因此同时保存三种表示：

- `helix7`：识别螺旋 7 残基（−1,1,2,3,4,5,6），用于替换骨架；
- `helix6`：去掉位置 4（不接触 DNA），用于与 B1H 数据对齐；
- `core4`：4 个核心位，用于跨数据集匹配同一条指头。

### 4.2 三联体与反平行

DNA 是反平行的，指头阵列的 N→C 方向对应 DNA 的 3'→5'。所以一个 9 bp 半位点与其三指阵列的对应关系是固定的（§2 的方向约定）。**这条错了，后面全错**，因此它有专门的单元测试：

```python
triplets_by_finger("AAACCCGGG") == {"F1": "GGG", "F2": "CCC", "F3": "AAA"}
```

### 4.3 半位点、spacer、二聚化

经典 ZFN 是两个单体各自结合一个 9 bp 半位点，中间留 5–7 bp spacer，两个 FokI 催化域在 spacer 上二聚化后切割。spacer 6 bp 最常见，5 或 7 也可用但效率与相位会变。**切割位点落在 spacer 中央**——本方案 `TargetSite.cut_offset_in_site` 用 `len(left) + (len(spacer)+1)//2 - 1` 计算，并给出输入坐标（负链做翻转），可以直接拿去设计同源重组供体或测序引物。

### 4.4 设计规则（写进打分器的那几条）

来自公开综述与领域惯例（详见 `docs/数据来源与许可.md`）：

1. 优先 **GNN** 三联体（G 开头），避免 CNN/TNN；
2. 避开含 **CpG** 的三联体（甲基化会削弱结合）；
3. 避开已知 SNP、重复序列、低复杂度区、旁系同源高度相似区；
4. spacer 优先 6 bp；
5. 位点自身不能是回文/强反向重复（会导致自行二聚、发夹、以及"自己把自己当脱靶"）；
6. 需要查染色质可及性（本工具**不做**，只在文档里要求人工核）。

**这些规则没有一条是"活性预测"**，它们只是让候选从"明显不像"里被剔除。这正是分数上限存在的意义：`A` 不代表"会成功"，只代表"按这套规则没发现明显毛病"。

### 4.5 阵列长度：三指 / 六指 / 自定义（2–12 指）

| | 三指阵列 | 六指阵列 |
|---|---|---|
| 每个单体读多少 DNA | **9 bp** | **18 bp** |
| 蛋白长度（本工具输出） | 90 aa（1AAY 骨架） | 184 aa（两个三指模块 + TGEKP 连接） |
| 基因组唯一性 | **通常不唯一**，必须靠成对使用 | 显著提高，但仍不保证 |
| 指头库上下文证据 | F2/F3 有实测；F1 需兜底 | F2/F3、F5/F6 有实测；**F1/F4 需兜底** |
| 模块间界面 | 不存在这个问题 | **完全未验证**（无结构、无活性数据） |
| 适用场景 | 常规基因编辑（成对切割） | 需要更高特异性的位点、或单拷贝定位 |

三句话说明白：

1. **三指 ZFP 单独不唯一**。9 bp 在 3 Gb 基因组里统计上会出现很多次；ZFN 之所以能用，是因为它**成对**——左右两个单体各认 9 bp，合起来 18 bp 以上，且必须同时结合才能切割。所以"单个三指阵列"本来就不是设计目标，本工具默认输出的就是成对设计。
2. **六指阵列 = 两个三指模块串起来**。每个模块各自折叠（这一步有 1AAY 结构依据），中间用一个 TGEKP 连接肽。但**两个模块之间怎么相对取向、连接肽多长合适、界面会不会互相干扰，本工具没有任何证据**，只能给一个"结构上说得过去"的草稿。
3. **六指不等于更好，只等于更长**。更长的阵列能提高唯一性，也会带来合成难度、表达、折叠与模块耦合的新风险。第一次做某个位点，先用三指成对；确实需要单拷贝级特异性时再上六指，并预留验证通量。

实现上，阵列长度只是把半位点从 `3k` 换成 `3n`（`--fingers N`、GUI 里的「指头阵列」下拉框，3 / 6 / **自定义**）：扫描窗口变成 `3n + s + 3n`，每个半位点切出 `n` 个三联体，蛋白按 `n` 指模板装配。其余流程（可设计性、打分、脱靶、报告）完全共用同一套代码，因此**不同阵列长度的分数不可直接比较**（分母不同）。

#### 4.5.1 自定义指数（Custom，2–12 指）

除了 3 指与 6 指两个"有名有姓"的模板，工具还支持任意 2–12 指。做法是**三指一模块首尾相接**：

| 片段 | 来源 |
|---|---|
| N 端 `MERPYACPVESCDRRFS` | 1AAY 逐字符 |
| 模块内 F1→F2 `HIRIHTGQKPFQCRICMRNFS` | 1AAY 原生连接区（13 + 8 aa） |
| 模块内 F2→F3 `HIRTHTGEKPFACDICGRKFA` | 1AAY 原生连接区（13 + 8 aa） |
| 模块之间 `TGEKP` + 去 Met 的 N 端 | 与六指模板 `zif268_x2_junction` 同一个接法 |
| C 端 `HTKIHLRQKD` | 1AAY 逐字符 |

于是骨架长度恒为 **28n + 6**（n=3 → 90 aa，正好还原 1AAY；n=6 → 184 aa，与手写六指模板**逐字符相同**）。这两条等式是这段代码唯一的可信依据，`tests/test_custom_fingers.py` 用它们做断言。

**自定义指数要为以下代价负责**（报告与 GUI 横幅会一并提示）：

- 尾部不整除 3 时（4、5、7…指），最后一个模块是被截断的——它的 C 端不是自然的 `HTKIHLRQKD`，而是接了下个模块的 `TGEKP`；
- 模块 N 端指（第 1、4、7… 指）在 B1H 库里没有本位上下文数据，只能借用别的位置的实测指头，报告会标"非本位上下文"；
- 指数越多，模块界面越多，未验证的自由度越多。**8 指并不比 6 指更"高级"，只是更长。**

### 4.6 单体型 vs 组合型（两条不同的流水线，不是一个标签）

这两个词经常被混用，本工具把它们做成**两种不同的扫描方式**，由 `--architecture`（GUI 里的「构型」）切换。它们不是同一套结果换个名字——**位点数、单体数、打分分项、脱靶判据、融合校验全都不同**：

| | 组合型（paired） | 单体型（single） |
|---|---|---|
| 触发构型 | `paired_nuclease`（默认） | `single_activator` / `single_repressor` |
| 扫描窗口 | 左半位点 `3k` + spacer `s` + 右半位点 `3k` | **只有一个半位点 `3k`**（无 spacer） |
| 300 bp 输入、三指、s=5/6/7 | **1662** 个候选位点 | **584** 个候选位点（`(300-9+1)×2`） |
| 输出蛋白 | 两条单体（左 + 右），各自 NLS-ZF-FokI | **一条** NLS-ZF-效应域 |
| 是否切割 | 是（两个 FokI 必须二聚化） | **否**——它是 ZF-TF，不是剪刀 |
| 打分分项 | 8 项（含 `spacer`，权重 0.10） | **7 项**（无 `spacer`，余下权重按比例重归一化） |
| 脱靶判据 | 「一对半位点像不像」（`mm_left` + `mm_right`） | 「**一个**半位点像不像」（单侧 hamming） |
| 融合校验 | 只接受二聚化架构 | 遇到 `paired_nuclease` 直接抛 `FusionError` |

三个必须记住的点：

1. **单体型没有"脱靶少"的优势**。它的判据更宽（只看一侧），所以同一段序列上的 burden 与命中数**天然高于**组合型。实测 demo：单体型 burden 1.06、命中 2；组合型 burden 0、命中 0。这不是单体型更差，而是**度量的东西不一样**。
2. **两类分数不可直接比较**。单体型少了 spacer 分项、权重重新归一化，总分区间仍然是 0–100，但含义已变。跨构型比大小是无意义的。
3. **这条区别在代码里是被强制的，不是靠自觉**。`targets.scan_sequence(mode=...)` 分派扫描方式、`Designability.right` 允许为 `None`、`offtarget.search_single()` 独立实现、`score_design()` 按形态增删分项——否则 `--architecture` 极容易退化成一个"只改报告字符串的开关"（本工具早期就是这样，两种构型跑出完全一样的数）。`tests/test_single_mode.py` 用 8 个断言把这条区别钉住。

## 5. 总体架构

### 5.1 流水线

```text
                    ┌──────────────────────────────────────────────┐
   DNA 序列  ──────▶│ 1 ingest        读 FASTA/纯文本/stdin        │
   (FASTA/文本)     │    ↓  SequenceRecord                         │
                    │ 2 targetscan    双链枚举 3k-spacer-3k       │
                    │    ↓  TargetSite[]                           │
                    │ 3 designability 按指头库判定 full/partial/gap │
                    │    ↓  Designability[]                        │
                    │ 4 build         阵列枚举 + 骨架移植           │
                    │    ↓  ZfnDesign[]（含氨基酸序列）             │
                    │ 5 score         8 分项加权 + 脱靶负担         │
                    │    ↓  ScoreBreakdown / OffTargetReport       │
                    │ 6 report        JSON / TSV / 单文件 HTML      │
                    │ 7 fusion        NLS-ZF-VP64 / NLS-ZF-FokI     │
                    └──────────────────────────────────────────────┘
```

### 5.2 各阶段的输入/输出/失败模式

| 阶段 | 输入 | 输出 | 典型失败模式与处理 |
|---|---|---|---|
| ingest | 序列字符串 / `.fa` / stdin | `SequenceRecord` | 出现非 ACGTN 字符 → `IngestError`，**不静默丢弃**；超长序列给出警告 |
| targetscan | `SequenceRecord` | `TargetSite[]` | 序列短于窗口长度（`3k+s+3k`，三指 spacer 5 → 23 bp）→ 0 位点（合法结果，不是错误）；含 N 的窗口跳过并计数 |
| designability | `TargetSite` + `FingerLibrary` | `Designability` | 三联体无候选 → `gap`，**必须**在报告中显式列出缺失三联体 |
| build | `Designability` + 库 | `ZfnDesign[]` | 组合爆炸 → `max_per_finger` + `n_designs` 截断，按 tier 和排序 |
| score | `ZfnDesign` | `ScoreBreakdown` | 权重和 ≠ 1.0 → `ValueError`（拒绝在错误权重下出分） |
| offtarget | 设计 + 搜索空间 | `OffTargetReport` | 搜索空间超 `max_bp` → `truncated=True` 并在报告里标注 |
| report | payload | 5 个文件 | 目录不可写 → 抛异常，不吞 |
| fusion | 设计 + 元件库 | 融合草稿 | 元件序列缺失（如 FokI）→ 输出 `[FOKI_CD:user_supplied]` 占位符，`is_complete=False` |

### 5.3 数据模型（`zfn_design/models.py`）

```python
EvidenceLevel(str, Enum)   # MEASURED/LITERATURE → Tier1; VARIANT_UNVALIDATED/CODE_INFERENCE → Tier2; NONE → Tier3
FingerRecord(helix_id, triplet, helix7, evidence, source_type, source_id, assay, affinity_nM, split_position, notes)
SequenceRecord(name, seq, description, source)
TargetSite(seq_name, start, strand, left_half, spacer, right_half, site_seq)   # site_seq = left + spacer + revcomp(right)
ZfnDesign(design_id, target, fingers, partner_fingers, protein, partner_protein, score, offtarget, architecture, notes)
ScoreComponent(key, label_zh, raw, weight, weighted, detail)   # 每一项都能打印出算法依据
ScoreBreakdown(components, total, grade, warnings, notes)
OffTargetHit/OffTargetReport(hits, burden, exact_hits, truncated, summary())
```

**设计原则：每个数字都必须能追到一条规则或一条文献。** `ScoreComponent.detail` 里写的是人话（"首位 G（GNN 偏好）；含 CpG（甲基化风险，−30）"），导出到 HTML/TSV 后可以直接贴进实验记录本。

## 6. 各阶段详细设计

### 6.1 ingest

支持三种互斥输入：`--sequence`、`--fasta`、stdin。只接受 `ACGTN`（大小写不敏感），其余字符报错并指出位置。FASTA 支持多记录。

### 6.2 targetscan

`scan_sequence(..., mode=...)` 有两种模式（见 §4.6）：

- **`mode="paired"`（组合型，默认）**：对每条序列、每条链、每个 spacer 长度（默认 5/6/7），滑动一个 `3k + s + 3k` 的窗口（`k` = 每个单体的指头数，默认 3，六指时 `k=6`）。
- **`mode="single"`（单体型）**：窗口就是半位点本身 `3k`，没有 spacer、没有右半位点，`spacer=""`、`right_half=""`。

组合型：

```text
窗口 = L(3k) + S(s) + R(3k)
判定：窗口即候选（不做序列偏好过滤——过滤留给 designability 与 score）
存储：left_half = L；spacer = S；right_half = R（编码链写法）
site_seq = L + S + revcomp(R)   ← 不变量
```

坐标：`start` 是输入序列上的 **1-based** 起点。负链窗口按下式换算：

```python
start_input = len(seq) - (i + span) + 1
```

切割位点（负链已翻转）：

```python
cut_offset_in_site = len(left_half) + (spacer_len + 1) // 2 - 1
```

候选数量可预测（有单元测试对齐）：

```python
expected_site_count(n, spacers, both_strands) = sum(n - (3k+s+3k) + 1 for s in spacers) * (2 if both_strands else 1)
# 单体型不看 spacer：per_strand = max(0, n - 3k + 1)
```

> 300 bp 输入、三指、spacer 5/6/7、双链 → 1662 个候选位点；同样输入换成六指、spacer 5/6/7 → 位点数明显下降（窗口边长了一倍）；同样输入换成**单体型** → 584 个（`(300-9+1)×2`，与 spacer 无关）。这些数字不是"好位点数"，只是"符合条件的窗口数"。

#### 6.2.1 全基因组扫描 + 重复序列过滤

上面的枚举是在一小段输入里做的。真实项目要的是"在整个基因组里找"，这条路径单独实现（`zfn_design/genome.py` + `pipeline.run_genome()`），因为它和"把序列读进内存"是两种程序：

| | 小输入 | 全基因组 |
| --- | --- | --- |
| 读入 | 整条序列进内存 | 流式，一次只驻留一条染色体（分块 4 Mb） |
| 枚举 | 先列表再处理 | 生成器，边扫边写 `sites.tsv` |
| 过滤时机 | 事后过滤 | **构造候选之前**就跳过重复区与含 N 的窗口 |
| 脱靶 | 在输入序列上搜 | 默认**不搜**（要另跑一遍基因组），只给警告 |

**为什么必须避开重复序列**：重复区（Alu、LINE、SINE、卫星、rRNA 基因簇……）在基因组里天然有成千上万个近似拷贝。设计在重复区里的 ZFN 看起来"有一个靶点"，实际上到处都能结合——它不是单靶点，也没有位点特异性。这正是导师那句话的意思：

> 我们设计的 target 不能在重复序列中，否则在基因组会有很多拷贝，不是 single target 或者特异位点。

所以本工具做两件事：

1. **过滤**：读 RepeatMasker 注释（`.out` 或 `.bed` 两种格式），落在注释区间里的窗口**根本不产出**。实现用"合并区间 + 二分查询"，不用逐点布尔数组（人类基因组会吃掉 3 GB 内存）。
2. **查重**：扫过的每个候选按 `site_seq` 记一次；**同一段序列第二次出现时**标成 `multi_copy`，不参与设计、不计入可设计统计，并在报告里单独报数。重复注释只覆盖"已知"的重复；`multi_copy` 兜住注释漏掉的拷贝。

固定参数下，两条长链的边界不能漏：分块时每块向右多读 `窗口长度-1` 个碱基，负链起点按 `block_start + nb - i - span` 换算（`nb` = 本块长度）。这两处是最容易出现"分块结果 ≠ 整条结果"的地方，`tests/test_genome.py` 用 `chunk=17` 强制跨块、与 `scan_sequence` 逐条对齐来钉死它。

**性能与正确用法**（实测，纯 Python、单线程）：

```text
裸枚举             ≈ 500,000 窗口/秒   （2.0 µs/窗口）
+ 可设计性 + 写 TSV ≈  24,000 窗口/秒   （缓存三联体候选 + 批量 flush 之后）
```

3.1 Gbp 人类基因组、三指、spacer 5/6/7、双链 ≈ **186 亿** 个窗口——即使 50 万/秒也要 10 小时。所以全基因组模式的**正确用法不是全量枚举**，而是：

```bash
# 1) 先缩小范围（启动子/外显子/保守区），再叠加重复过滤
zfn-design scan --genome GRCh38.fa --regions promoters.bed --repeats GRCh38.fa.out \
                --spacers 5-7 --limit 200000 --out scan_out

# 2) 想在整条染色体上跑，就分批 + 提高 limit
zfn-design scan --genome chr1.fa --repeats rm.out --limit 2000000 --out chr1_scan
```

输出只有 `sites.tsv`（一行一个候选，Excel 直接打开）+ `report.json`；`--design N` 会额外给前若干个位点出设计（此时**没有做脱靶搜索**，报告里会明确标注）。

### 6.3 designability（本方案的核心机制）

对每个位点的**每个半位点**（组合型 2 个、单体型 1 个），各需要 3 个三联体（按 §2 的方向映射；六指时每个半位点 6 个）。对每个三联体查库：

- 有 Tier1 候选 → 该指位可用；
- 只有 Tier2 候选 → 该指位"有但是未验证"；
- 没有候选 → 该指位 `gap`。

位点级状态：

| 状态 | 条件 | 报告用词 |
|---|---|---|
| `full` | 全部指位都有 Tier1（组合型三指 = 6 个指位） | 可设计（全 Tier1） |
| `partial` | 有 Tier1/Tier2 但至少一个是 Tier2 | 可设计（含未验证） |
| `gap` | 至少一个指位无候选 | 缺口 |

并输出**三联体需求表**（`triplet_demand`）：按"该三联体在本输入的所有位点中出现的次数"排序，未覆盖的排前面。

> 这是本工具最实用的输出。以接入 B1H 之前的种子库为例，导入排名前 10–20 个三联体就能覆盖输入里绝大多数位点。demo（300 bp）上前几名是 ATC 594、GAT 594、AGC 450、GCT 442、CGA 432、TCG 430……
>
> 现在随包库已覆盖 64/64，这张表的主要用途变成**看上下文缺口**：哪些三联体在很多位点上只能用"非本位上下文"的指头。

### 6.4 build

对 `full`/`partial` 位点，每个指位取前 `max_per_finger` 个候选（按 tier → affinity → id 排序），做笛卡尔积，按"tier 之和"升序取前 `n_designs` 个。

蛋白序列用**骨架移植（backbone swap）**：保留 Zif268（PDB 1AAY）的真实骨架与连接区，只替换三段 7 残基识别螺旋。

```text
MERPYACPVESCDRRFS{h1}HIRIHTGQKPFQCRICMRNFS{h2}HIRTHTGEKPFACDICGRKFA{h3}HTKIHLRQKD
                   └─ F3 ─┘                     └─ F2 ─┘                └─ F1 ─┘
```

> 注意模板里 `{h1}/{h2}/{h3}` 的位置：**字符串从左到右是 F3→F2→F1**（因为 N→C 对应 3'→5'）。把 1AAY 的三条真实螺旋填回去必须**逐字节还原** 90 aa 的天然序列，这是全项目最重要的一条真值断言。

模板允许 `X` 作为占位符（B1H 导入的指头缺位置 4 的信息时使用），但会在 `warnings` 里明确标注。

### 6.5 score

总分是 8 个 0–100 分项的加权和（权重外置在 `data/scoring_weights.json`，和为 1.0，改它不需要改代码）：

| key | 权重 | 含义 | 规则 |
|---|---|---|---|
| `evidence` | 0.30 | 指头证据强度 | 全部 Tier1 → 100；含 Tier2 → 45；含 Tier3 → 0 |
| `offtarget` | 0.20 | in silico 安全性 | `max(0, 100 − 25 × burden)` |
| `subsite` | 0.18 | 三联体质量 | 6 个指位三联体的均值；单个三联体：首位 G=100 / A,T=62 / C=40，含 CG −30，三联同碱基 −12，下限 0 |
| `spacer` | 0.10 | spacer 长度 | 6 bp → 100；5 或 7 → 72；其他 → 40 |
| `gc_balance` | 0.07 | 位点 GC | 0.40–0.60 → 100；0.30–0.70 → 70；其余 → 30 |
| `finger_diversity` | 0.07 | 阵列多样性 | 无相邻相同螺旋 → 100；有 → 55 |
| `complexity` | 0.04 | 序列复杂度 | 最长同碱基串 ≤4 且 2-mer 重复 ≤2 → 100；≥7 或 ≥5 → 25；其余 65 |
| `self_complementarity` | 0.04 | 自身互补风险 | 无 ≥6 bp 内部反向重复 → 100；有 → 0 |

等级：`A ≥ 85`、`B ≥ 70`、`C ≥ 55`、其余 `D`。

**分数怎么读：**

- `evidence` 占 0.30，意味着"用未验证指头"几乎不可能拿到 A——这是刻意的：**证据质量比序列漂亮重要**；
- 一个 A 分设计仍然可能在细胞里完全没活性（§3.2a）；
- 所有 `ScoreBreakdown.warnings` 必含一句："所有计算输出都必须实验验证；本分数不是活性预测。"

> demo 的 300 bp 输入上，唯一可设计的位点（`demo_target:25`）得 83.8 分（B）：证据满分、脱靶 0 负担、spacer 6 bp，但位点 GC 75%（扣分）且**存在 9 bp 内部反向重复**（自互补项 0 分）——因为该 demo 位点左右半位点恰好相同，这是有意造的"坏例子"，用来验证扣分链路真的会响。

### 6.6 off-target（in silico）

算法（语义参照 ZFN-Site / Tagger 的"半位点 + spacer + 错配"模型<sup>[3]</sup>，但**未**实现其完整打分矩阵）：

```text
for 每条序列 × 每条链 × spacer∈{5,6,7} × 每个位置 i:
    if hamming(window_left, left_half) <= max_mm_left
       and hamming(window_right, revcomp(right_half)) <= max_mm_right
       and 该坐标不是 on-target（两链一并排除）
    then 记录命中，burden += weight(total_mm)
weight(0) = 1.00, weight(1) = 0.25, weight(2) = 0.06
# 全基因组模式下每侧上限 2、总错配最多 4，权重表另补 0.015 / 0.004（见 §6.6.1）
```

**必须一起排除 on-target 的两条链**：回文位点在反链上会与自身完全一致，只排除本链会把它报成"0 错配脱靶"（我们真的在开发中踩到过这个坑）。

**边界：**

- 搜索空间默认 = 输入序列本身（300 bp 级）。要搜全基因组，见 §6.6.1；
- `max_bp` 默认 5,000,000，超出即 `truncated=True` 并在报告里标注"未搜完"；
- `burden` 是**序列相似度的加权和**，不是切割概率；结合脱靶 ≠ 切割脱靶。

#### 6.6.1 全基因组脱靶评分（`--ot-designs N`）

小输入上的脱靶搜索和"扫全基因组"是两种程序：前者可以整条读进内存暴力枚举，后者必须流式，而且单个设计的窗口数就是 3 Gbp 级。所以基因组模式默认**不做**脱靶；要做得显式打开：

```bash
zfn-design scan --genome GRCh38.fa --regions promoters.bed --repeats GRCh38.fa.out \
                --design 2 --ot-designs 3 --ot-max-mm 2 --out scan_out
```

实现（`zfn_design/offtarget_genome.py`）：

1. 对分数最高的 `N` 个设计，取它的 `spacer` 长度，**在整条基因组上逐位置**比对左半位点与 `revcomp(右半位点)`；
2. 两条方向各扫一遍（位点在正链 / 负链），左右半位点相同时自动去重，否则同一个物理位点会被数两次；
3. 权重按**总错配数**取：`0→1.00, 1→0.25, 2→0.06, 3→0.015, 4→0.004`（每侧上限 2，故总计最多 4）；
4. 命中数超过 `--ot-max-hits` 时清单截断，但 `burden` 与 `by_mm` 仍是全量统计；
5. 算完把该设计的 `offtarget` 分项**替换**成全基因组版本再重新打分，`score.notes` 里记下替换前的总分。

**性能与引擎**：装了 numpy 时走向量化路径（每 4 Mb 块做 18 次向量比较），没装就退回纯 Python 循环。实测 324 kb 基因组、2 个设计、错配 ≤2/侧：numpy 0.01 s；纯 Python 约 40 倍慢。3.1 Gbp 的人类基因组按此推算，numpy 下每个设计每侧约 1–2 分钟——这就是为什么默认只对"分数最高的 N 个"做，而不是全部。

**这一节必须说的三句话：**

- 基因组尺度的 `burden` 仍然只是**序列相似度**，不是切割概率；
- 它**不替代** ZFN-Site / BLAT 这类带索引的工具，只是让"这个设计在基因组里像不像别的地方"有一个可复现的数字；
- 0 错配的命中（`by_mm["0"]`）才是必须逐个看的；3/4 错配的权重低到只用于排序。

### 6.7 report

一次运行产出 5 个文件（基因组模式 + `--ot-designs` 时多一个 `offtargets.tsv`）：

| 文件 | 用途 |
|---|---|
| `report.json` | 完整机器可读结果（含每个分项的 raw/weight/weighted/detail） |
| `report.html` | **单文件、零外部依赖**的可视化报告（可直接归档/发给合作者） |
| `sites.tsv` | 全部候选位点（Excel 可开） |
| `designs.tsv` | 全部设计 + 分数 + 蛋白序列 |
| `fusions.json` | 融合构型草稿 |
| `offtargets.tsv` | 全基因组脱靶命中（`design_id / chrom / start0 / strand / spacer / mm_*`），仅 `--ot-designs` 时产出 |
| `sites.tsv`（基因组模式） | 全部候选位点，逐行流式写出；`designability=multi_copy` 表示该序列在基因组里出现多次 |

HTML 报告结构：免责横幅 → 统计卡 → 输入 → 指头库 → 位点表 → **三联体需求表** → 设计卡（分数条 + 分项表 + 蛋白序列 + 前 10 脱靶）→ 融合表 → 权重表。

### 6.8 fusion

元件库（`data/fusion_parts.json`）每条都带 `evidence_level`：

| 元件 | 序列 | 证据 | 说明 |
|---|---|---|---|
| `NLS_SV40` | `PKKKRKV` | verified | Kalderon 1984<sup>[4]</sup> |
| `VP64` | `DALDDFDLDMLGS`×4 | **needs_review** | 常用构建，但**必须逐碱基核对**后再合成 |
| `FokI_CD` | *（null）* | **user_supplied** | 催化域序列未随包提供；输出占位符 `[FOKI_CD:user_supplied]` |
| `linker_GGGGS` | `GGGGS` | verified | 柔性连接 |

**故意不内置 FokI 序列**：它是有专利与许可背景的编码序列，且不同来源的边界定义（486 aa 全长 / 196 aa 催化域）差异会影响活性。宁可让报告显示 `is_complete=False`，也不要给一段"看起来对"的序列让人直接去合成。

## 7. 指头库：数据从哪来、怎么进来

### 7.1 首选数据源：Princeton B1H（Persikov 2015）

- 覆盖：全部 64 个 3 bp 靶点，>160,000 个 domain–DNA 互作<sup>[2]</sup>；
- 获取：`https://zf.princeton.edu/b1h/download.html`，需填 Name / Affiliation / Email，选 **F2 union** 或 **F3 union**（免费、非商业）；
- 格式：每个三联体 × 每个指位一个文本文件，每行 = 该螺旋在 −1,1,2,3,5,6 位的氨基酸 + 对数归一化频率；
- 本方案**不**脚本绕过申请表单（尊重作者的非商业申请机制）。

拿到后一条命令导入：

```bash
zfn-design library import-b1h ./F2_union --split F2 --top 8 --out f2.csv
zfn-design library import-b1h ./F3_union --split F3 --top 8 --out f3.csv
zfn-design library info f2.csv
```

导入器会把每行的 6 个氨基酸补成 7 残基（位置 4 不接触 DNA，默认填 `L`，可用 `--pos4` 改），并按频率取 top N。

### 7.2 随包库：B1H 全量接入后的实际状态

本项目已经把 **F2 union + F3 union 全量接入**，随包库从 3 条扩到 **1,027 条**，覆盖 **64/64** 个三联体：

| 指标 | 数值 |
|---|---|
| 记录数 | 1,027（F2 513 / F3 513 / 种子 1） |
| 覆盖三联体 | 64 / 64 |
| 证据等级 | 全部 Tier1（1,024 `measured` + 3 `literature`） |
| 每三联体每上下文 | 取频率 top 8 |
| 位置 4 | 数据中不存在，统一填 `L`，并在 `notes` 里写明"未测" |

由 `tools/build_library.py` 从原始目录生成 `data/finger_library_b1h.csv`；重跑命令：

```bash
python tools/build_library.py --f2 ./F2_union --f3 ./F3_union --top-n 8
```

**一个必须说清的局限：上下文缺口。** B1H 数据集只提供阵列中 **F2 与 F3 两个位置**的数据，没有 F1。严格按"本位上下文"匹配，任何位点的 F1 指位都会缺候选。本方案的处理是：**退用同一三联体在其它位置实测的指头**，并把该指位记进 `HalfSitePlan.context_fallback`，在报告与 `warnings` 里显式提示"这些指头在该位置的行为未经验证"。

这是一个**有意的工程折中**：宁可给一个标注了风险的候选，也不假装数据完整。真实项目里 F1 位应优先选有本位数据的指头，或用湿实验补测。

### 7.3 种子库：3 条可复核的锚点

`data/finger_library_seed.csv` 仍然保留，只有 PDB **1AAY**（Zif268）的三条识别螺旋：

| helix_id | triplet | helix7 | split | 来源 |
|---|---|---|---|---|
| `1AAY_F1` | GCG | `RSDELTR` | F1 | PDB 1AAY 晶体结构 |
| `1AAY_F2` | TGG | `RSDHLTT` | F2 | 同上 |
| `1AAY_F3` | GCG | `RSDERKR` | F3 | 同上 |

选它的理由：**可被任何人用一条命令复核**（`https://www.rcsb.org/fasta/entry/1AAY`），且外侧两个三联体同为 GCG，因此这条记录不受"F1/F3 到底谁读 5' 端"的方向约定影响，是最安全的锚点。

代价：覆盖 2/64。**这是刻意的**——种子库的作用是"证明骨架正确"，不是"够用"。它现在**不是默认库**（默认是上面那份 1,027 条的 B1H 库），只在两种情况下出场：`--library` 显式指定，或项目被裁剪成不含 B1H 数据的可分发版本。此时工具会在每次运行时打印：

> 指头库只覆盖 2/64 个三联体，绝大多数位点会被判为缺口。这是随包种子库的预期表现——真实项目请导入 B1H 数据集。

### 7.4 绝不冒充

`evidence_level` 是硬约束：

- `code_inference`（识别密码枚举出来的指头）**可以**入库，但永远判为 Tier2，永远触发"未验证"警告，永远拉低 `evidence` 分；
- 任何"没有出处"的记录不允许标成 `measured` / `literature`；
- `library validate` 会检查字段合法性；CSV 里每一行都必须有 `source_type` + `source_id`。

## 8. 验证计划（湿实验闭环）

计算只负责"把候选缩到可做的数量"。真正决定成败的是这张表：

| 步骤 | 方法 | 判据 | 备注 |
|---|---|---|---|
| 1. 质粒构建 | 按 `fusions.json` / `designs.tsv` 的蛋白序列做密码子优化 | 测序无误 | ⅹ不要直接抄 `[FOKI_CD:user_supplied]` 占位符 |
| 2. on-target 活性 | **T7E1** 或 amplicon 深度测序 | 与阴性对照比，indel% 显著 | T7E1 灵敏度约 1–5%；NGS 更定量 |
| 3. in silico 脱靶复核 | ZFN-Site（`epd.expasy.org/tagger/`） | 列出 top 候选位点 | 与本地 `offtarget.py` 结果交叉核对 |
| 4. 脱靶实测 | 对 top 候选做 amplicon NGS | 目标位点 vs 预测位点 | 至少覆盖 burden 最高的 5–10 个 |
| 5. 重复 | 至少 **2 次独立重复** | 趋势一致 | 单次结果不足以排序候选 |

**预期成功率：** 按 §3.2a，模块化组装的成功率本就低。若 10 个候选里 2–3 个有可测活性，属于正常范围；若 0 个有活性，优先怀疑指头库覆盖率与相邻指头界面，而不是"打分器调错了"。

**排序候选的顺序建议：** 先看 `evidence`（Tier1 优先）→ 再看 `offtarget.burden`（越低越好）→ 最后才看总分。总分是给人看的，前两项才是决策依据。

## 9. 局限性（诚实清单）

1. **不预测活性**。没有任何一项分项是从活性数据拟合出来的。
2. **不做全基因组脱靶**。默认只在输入序列里搜。
3. **不建模相邻指头界面**。这是模块化组装失败的主因<sup>[1]</sup>，本方案只用 `finger_diversity` 做一个极粗的代理指标。
4. **不查染色质/甲基化/SNP**。需要外部数据（ENCODE、Roadmap、dbSNP）人工核。
5. **库的上下文不完整**。B1H 只测了 F2/F3 两个位置；F1 位靠"同三联体跨位置"兜底，行为未验证。覆盖率 64/64 不等于"每个位点都有本位实测数据"。
6. **FokI 催化域序列未内置**；`VP64` 标为 `needs_review`。
7. **spacer 默认只枚举 5/6/7**；自定义模式可以指定任意长度（`--spacers 8` 或 GUI 的「自定义」），但 5–7 之外的相位与效率没有依据。
8. **多模块阵列的模块间界面完全未验证**。六指模板只是"两个 1AAY 模块 + TGEKP 连接"，自定义指数用的是同一接法逐段拼接；两者都没有任何结构或活性证据，模块 N 端指（F1/F4/F7…）也没有本位上下文数据（见 §4.5、§7.2）。
9. **不处理 ZFP-TF 的间距效应**（启动子上下文的核小体排布、激活域与转录起始位点的距离）。
10. **单线程纯 Python**。300 bp 输入秒级；Mb 级输入需要先切窗（见 §12）。

## 11. 运行与复现

```bash
# 0) 无需安装第三方包（纯标准库）
python -m zfn_design info

# 1) 看骨架/架构/权重/元件证据状态
python -m zfn_design library info            # 指头库覆盖
python -m zfn_design scan --fasta gene.fa    # 只列位点，不设计

# 2) 跑完整流水线
python -m zfn_design run \
    --fasta gene.fa \
    --out out/ \
    --n-designs 5 \
    --max-sites 20 \
    --fingers 3 \
    --spacers 5-7 \
    --architecture paired_nuclease
```

关键参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--fingers` | 3 | 每个单体的指头数：3（9 bp 半位点）或 6（18 bp 半位点） |
| `--spacers` | `5,6,7` | 支持 `6` / `5,6` / `5-7` 三种写法；只要 6 可显著加速 |
| `--single-strand` | 关 | 只扫正链（调试用） |
| `--max-tier` | 2 | 允许使用 Tier2 指头；设 1 则只用已验证 |
| `--n-designs` | 5 | 每个位点的设计数（委托要求 3–10） |
| `--max-per-finger` | 2 | 每个指位取几个候选做组合 |
| `--max-sites` | 20 | 最多处理几个位点（0 = 不限） |
| `--offtarget-fasta` | 无 | 额外的脱靶搜索空间 |
| `--weights` | 内置 | 自定义权重 JSON |

输出解读顺序：先看 HTML 顶部统计卡（`gap` 比例）→ 再看三联体需求表 → 再看设计卡的 `evidence` 与 `offtarget` 分项 → 最后看总分。

## 12. 后续路线（按性价比排序）

1. **导入 B1H 覆盖**（最高价值）：64/64 覆盖后，`gap` 比例从 99.9% 降到接近 0。
2. **PWM 打分器插件**：把 Princeton `pwm_predict` 的输出作为 `pwm` 分项接入（接口已预留）。
3. **外部打分器**：读取 ZFDesign（MTA）或实验数据 CSV，作为 `external` 分项。
4. **长序列分窗**：>100 kb 时按 50 kb 窗口滑，输出合并。
5. **基因组脱靶后端**：用 `pyfaidx` 或预建 k-mer 索引替代暴力扫描。
6. **相邻指头界面代理**：用 B1H 里成对指头的数据估一个"界面惩罚"，向 CoDA/OPEN 的上下文依赖靠近。
7. **密码子优化 + 载体输出**（GenBank/`*.gb`）。

## 附录 A. 打分公式（可直接抄进方法学部分）

```text
设设计 d 的 8 个分项原始分为 r_i ∈ [0,100]，权重 w_i，且 Σ w_i = 1：

    S(d) = Σ_{i ∈ {evidence, offtarget, subsite, spacer,
                  gc_balance, finger_diversity, complexity, self_complementarity}}
           w_i · r_i

其中脱靶项：

    r_offtarget(d) = max( 0, 100 − 25 · Σ_{h ∈ H(d)} ω(mm(h)) )
    ω(0) = 1.00,  ω(1) = 0.25,  ω(2) = 0.06,  ω(>2) = 0

三联体项（T(d) 为 6 个指位的三联体集合，b 为首位碱基基准分）：

    r_subsite(d) = (1/6) · Σ_{t ∈ T(d)} max( 0, b(t) − 30·[CG ⊂ t] − 12·[|{t}| = 1] )

    b(t) = 100  若 t 的首位 = G
         = 62   若 t 的首位 ∈ {A, T}
         = 40   若 t 的首位 = C

等级：A ≥ 85，B ≥ 70，C ≥ 55，其余 D。
```
