# 术语表：把 ZFN 的黑话翻成人话

> 用法：先读"三句话版本"，再看需要的那一节。每条都给了**一句话定义 + 一个类比 + 在本项目里对应哪个字段/文件**。
> 如果只想理解报告在说什么，读 §1 和 §5 就够。

---

## 0. 三句话版本

1. **锌指（ZF）是一小段能"摸"DNA 的蛋白模块**，一个模块认 3 个碱基；三个模块串起来就认 9 个碱基。
2. **ZFN 是"锌指 + 剪刀"**：两个这样的模块组分别摸住左右各 9 个碱基，把剪刀（FokI）凑到一起，就在中间剪断 DNA。
3. **本程序干的事**：在给定的 DNA 里找出所有"能这么摸、能这么剪"的位置，给每个位置配上具体的蛋白序列，并老实告诉你**哪些位置其实没数据、做不了**。

---

## 1. 基础概念

**DNA 双链 / 编码链 / 反义链**
DNA 是两条互补的链拧在一起。习惯上把基因里"能直接翻译成蛋白"的那条叫**编码链**，另一条叫反义链。写序列时默认写编码链、5'→3'。
*类比*：一条拉链的两侧，齿是互补的；你说"第 5 个齿"时得说清是哪一侧。
*项目里*：`SequenceRecord.seq` 恒为编码链写法；负链位置用 `TargetSite.strand = "-"` 标记。

**反向互补（revcomp）**
把序列倒过来再从 A↔T、C↔G 互换。`GCGTGGGCG` 的反向互补是 `CGCCCACGC`。
*类比*：把一句话从镜子里反过来读，还得把每个字母换成它的配对字母。
*项目里*：`sequtil.revcomp()`。**这是全项目最容易搞错的一个函数**，凡是"右半位点"都要经过它。

**5' / 3' 端**
DNA 链有方向性。写 `5'-ACGT-3'` 和写 `3'-ACGT-5'` 是两段不同的序列。
*项目里*：所有半位点、三联体都以 5'→3' 存。

**碱基 / bp**
A、T、C、G 四种碱基；bp = base pair，碱基对，用来量 DNA 长度。"9 bp"就是 9 个碱基那么长。

**三联体（triplet）**
连续 3 个碱基，如 `GCG`、`TGG`。一个锌指指头认一个三联体。一共 4³ = **64 种**。
*项目里*：`FingerRecord.triplet`；指头库就按它建索引。

**氨基酸 / 残基 / aa**
蛋白的字母表，20 种，用单字母表示（A、R、D……）。"残基"就是"蛋白链上的一个位置"。
*项目里*：`helix7` 是 7 个氨基酸的字符串，如 `RSDELTR`。

## 2. 锌指与阵列

**锌指（ZF, zinc finger）**
一类靠锌离子稳定的小蛋白结构域。**本文默认指 C2H2 型**（半胱氨酸×2 + 组氨酸×2 配位一个锌）。一个指头约 30 个氨基酸。
*类比*：一只"手"，手指尖（识别螺旋）能伸进 DNA 大沟里摸碱基。

**识别螺旋（recognition helix）**
指头里真正插进 DNA 大沟的那段 α 螺旋。**7 个关键位置**（编号 −1, 1, 2, 3, 4, 5, 6）决定它认哪 3 个碱基。
*项目里*：`helix7`，例如 `RSDELTR`。

**core4 / core sequence**
识别螺旋 4 个**最决定特异性**的位置（−1, 2, 3, 6）。文献（Persikov 2015）证明这 4 位管大部分事，1 和 5 位比较"随便"。
*项目里*：`FingerRecord.core4`，用于跨数据集匹配"这是不是同一条指头"。

**指位 F1 / F2 / F3**
一个三指阵列里第 1、2、3 个指头，**从 N 端数起**。
⚠️ **N 端对应 DNA 的 3' 端**（蛋白和 DNA 是反平行的）。所以 F1 读的是半位点**最右边**那 3 个碱基。
*项目里*：`triplets_by_finger("GCGTGGGCG") == {"F1":"GCG","F2":"TGG","F3":"GCG"}`——注意 F1 拿的是后三位。

**半位点（half-site）**
一个单体阵列认的那段 DNA：**三指 = 9 bp，六指 = 18 bp，n 指 = 3n bp**。ZFN 有两个半位点（左、右）。
*项目里*：`left_half` / `right_half`；长度 = 3 × 指头数。

**spacer（间隔区）**
两个半位点中间那段**蛋白不摸**的碱基。经典 ZFN 是 5–7 个，**6 个最常见**。
*类比*：两个人各抓住绳子的一头，中间留一段空绳，两把剪刀才能在那段空绳上汇合。
*项目里*：`TargetSite.spacer`；打分项 `spacer`（6 bp 得满分）；GUI/命令行可切「默认 5–7」或自己指定。

**阵列（array）/ 多指蛋白**
把多个指头串成一条蛋白链。本方案支持 **3 指（9 bp）**、**6 指（18 bp）**，以及 **自定义 2–12 指**（读 3n bp）。
*项目里*：`--fingers N`；GUI 的「指头阵列」下拉框（三指 / 六指 / 自定义）。

**三指阵列 / 六指阵列（3-finger / 6-finger array）**
三指 = 一个 90 aa 的单体，认 9 bp；六指 = 两个三指模块用 TGEKP 串起来，184 aa，认 18 bp；自定义 n 指（2–12）= 三指模块首尾相接，长度 28n + 6 aa。
⚠️ **三指阵列单独用时不唯一**：9 bp 在 3 Gb 基因组里会出现很多次。ZFN 靠"左右两个单体成对"才获得特异性；要单拷贝级定位，要么成对使用（默认），要么上六指。
⚠️ 六指也不是"更好"，只是"更长"：两个模块之间的界面、连接肽长度、相对取向，本工具**没有任何证据**。
*项目里*：`framework_templates.json` 的 `zif268_x2_junction`。

**单体型 / 组合型（single / paired，ZF-TF vs ZFN）**
**组合型**是两个单体一起干活：左边认一段、右边认一段，中间留 spacer，两个 FokI 必须碰在一起才有切割活性——这就是经典 ZFN（剪刀）。
**单体型**只有一个阵列：认一段 DNA，后面直接接激活域（VP64）或抑制域（KRAB），**不切割**——它是 ZF-TF（人工转录因子）。
⚠️ 两者不是"同一套结果换个名字"：单体型只扫一个半位点（无 spacer），打分少一个分项，脱靶按"单个半位点像不像"判，所以**命中数天然更多、分数不可跨构型比较**。
*项目里*：`--architecture paired_nuclease` = 组合型；`single_activator` / `single_repressor` = 单体型；判定在 `pipeline.PAIRED_ARCHITECTURES`。

**骨架 / 框架 / scaffold / backbone**
指头阵列里**除识别螺旋以外**的部分（β 折叠、连接区、锌配位残基）。设计时通常不动它，只换 7 残基的螺旋。
*项目里*：`framework_templates.json` 里的 `zif268_1aay`；做法叫 **backbone swap**（骨架移植）。

**连接区（linker, TGEKP）**
相邻指头之间那 5 个氨基酸，是"指头之间的关节"。**它也是模块化组装失败的原因之一**：换一个指头，关节角度变了，特异性也会变。
*项目里*：1AAY 骨架里真实存在（`HIRIHTGQKPFQC` 这段里就含着）；`finger_diversity` 只是它一个很粗的代理。

**Zif268 / 1AAY**
一个经典的天然三指蛋白，PDB 编号 **1AAY** 是它的晶体结构。本方案用它做骨架模板，因为**任何人都能一条命令复核**。
*项目里*：`data/finger_library_seed.csv` 的 3 条记录（骨架模板的来源）+ `framework_templates.json` 的序列模板。

## 3. 核酸酶与切割

**FokI**
一个需要**两个催化域靠在一起**才有活性的核酸酶。ZFN 就是把 FokI 的催化域接到锌指阵列的 C 端。
*类比*：一把要两个人同时按下才工作的剪刀。

**ZFN（zinc finger nuclease）**
锌指阵列 + FokI 催化域。经典构型：两个单体，各摸一个半位点，中间留 spacer，FokI 在 spacer 上二聚化并切割。

**切割位点（cut site）**
实际被剪断的位置，大致在 spacer 中央。
*项目里*：`TargetSite.cut_site_input`（已换算成输入序列的坐标，负链也翻好了）。

**NLS（核定位信号）**
一小段让蛋白被运进细胞核的肽，最常用的是 SV40 大 T 抗原的 `PKKKRKV`。
*项目里*：`fusion_parts.json` 的 `NLS_SV40`。

**VP64**
四个 VP16 激活域串起来的转录激活模块，常接在锌指后面做"人工转录因子"（ZF-TF）。
*项目里*：`VP64`，标记为 **needs_review**——序列来源常见但版本有差异，合成前必须自己核对。

**KRAB**
一个转录抑制域，接在锌指后面用来"关掉"某个基因。本方案列了架构但**没有内置序列**。

**融合构型（fusion architecture）**
`NLS + ZF + 效应域` 的排列方式。本方案支持三种：`paired_nuclease`（经典 ZFN）、`single_activator`（ZF-VP64）、`single_repressor`（ZF-KRAB）。

## 4. 数据与证据（本项目最看重的部分）

**B1H（bacterial one-hybrid）**
一种高通量测特异性的实验方法：让每个指头变体去"钓"一段 DNA，钓得多的说明结合强。Persikov 2015 用它筛了全部 64 个三联体。
*项目里*：指头库的首选数据源；`library import-b1h` 导入器。

**B2H / reporter assay**
另外两类实验（双杂交、报告基因）。也能产出可信数据，只要能给出处就能进 Tier1。

**PWM（position weight matrix，位置权重矩阵）**
描述"这段序列各个位置上偏好哪个碱基"的表格。可以理解为"结合的概率画像"。
*项目里*：预留了 `pwm` 打分器的接口（尚未实现，需要用户提供 `pwm_predict` 的输出）。

**证据层级（evidence_level）—— 本项目的核心设计**

| 层级 | 取值 | 含义 | 能不能直接拿去合成 |
|---|---|---|---|
| Tier1 | `measured` / `literature` | 有实验或晶体结构支持，且能给出 DOI/PDB 出处 | 可以（仍需湿实验验证活性） |
| Tier2 | `variant_unvalidated` / `code_inference` | 由识别密码/规则推导，**未经实验验证** | 不建议；报告会显式警告 |
| Tier3 | `none` | 没数据 | 不能，位点判为 `gap` |

*为什么重要*：网上很多"锌指设计"表格是把识别密码直接枚举出来的，看起来很像真的。本方案**绝不允许**把 Tier2 混成 Tier1——这是它和"看起来很厉害的表格"的根本区别。

**可设计性（designability）**
每个位点的状态：`full`（6 个指位全有 Tier1）、`partial`（有但含未验证）、`gap`（至少一个指位没数据）。
*项目里*：`designability.py`；HTML 报告顶部统计卡。

**缺口（gap）**
指头库里没有这个三联体的任何记录。**不是错误，是事实**——报告会把它列出来，并给出"该补哪些三联体"的清单。

**三联体需求表（triplet_demand）**
按"在本输入里出现的次数"给缺失三联体排序。库不完整时这是最实用的输出：补前 10–20 个就能覆盖绝大多数位点。库完整后它的用途变成**看上下文缺口**。
*项目里*：`designability.triplet_demand()`；HTML 报告第 4 节。

**覆盖度（coverage）**
指头库覆盖了多少个三联体，如 `64/64`。
*项目里*：`library.coverage_stats()`。

**本位上下文 / 上下文缺口（context fallback）**
同一个三联体的指头，在阵列的 F1、F2、F3 三个位置上表现并不一样——相邻指头的界面会改变特异性。所以"这个三联体有指头"不等于"在这个位置有指头"。当库里缺某个位置的数据时，本程序退用同一三联体在别的实测过的位置的指头，并标为 `context_fallback`（行为未验证）。
*项目里*：`HalfSitePlan.context_fallback`；报告里的「非本位上下文」警告。

## 5. 打分相关的词

**on-target / off-target**
on-target = 你想切的位点；off-target = 别处"长得像"、可能被误切的位置。

**burden（脱靶负担）**
本方案对脱靶风险的量化：所有相似位点按错配数加权求和（小输入 0/1/2 错配 = 1.00 / 0.25 / 0.06；全基因组模式还用到 3/4 错配 = 0.015 / 0.004）。
⚠️ **它不是"切割概率"**，只是"序列相似度的加权和"。

**全基因组脱靶评分（genome-wide off-target scoring）**
把某个设计拿到**整条基因组**上搜"像它的位点"，再按错配加权求和。类比：小输入的脱靶搜索像"在自家小区里找同名的人"，全基因组像"在全国户籍系统里找"。
为什么不默认做：3 Gbp × 每条链 × 每个位置，单个设计就是十亿级的比对；所以本工具默认只对**分数最高的 N 个设计**做（`--ot-designs N`），结果写进 `offtargets.tsv`。
⚠️ 它给出的是"这个设计在基因组里像不像别的地方"的**可复现数字**，仍然不是切割概率，也不替代 BLAST / ZFN-Site 这类带索引的工具。

**脱靶分（offtarget score）**
把 burden 换算成 0–100 分：`max(0, 100 - 25 × burden)`。一个 0 错配命中（权重 1.00）就让这一项掉 25 分。
项目里：`zfn_design/score.py::_offtarget_component`；全基因组模式下该分项会被基因组扫描的结果**替换**，`score.notes` 里记着替换前的总分。

**错配（mismatch, mm）**
候选位点与目标位点不一致的碱基数。`mm=1` 表示差 1 个碱基。

**in silico**
"在计算机里"，相对 in vitro（试管里）/ in vivo（活体里）。本方案所有输出都是 in silico。

**启发式（heuristic）**
"按经验规则来，不保证最优"的做法。本方案的打分器就是启发式——**它不预测活性**。

**权重（weight）**
每个分项在总分里占多大比例。外置在 `data/scoring_weights.json`，改它不用改代码。
*类比*：考试各题的分值。

**等级 A/B/C/D**
`A ≥ 85`、`B ≥ 70`、`C ≥ 55`、其余 `D`。
⚠️ **A 不代表"会成功"**，只代表"按这套规则没发现明显毛病"。

**免责声明（disclaimer）**
报告顶部那段话。不是客套：任何设计在合成前都必须做 T7E1 或 amplicon 测序验证。

## 6. 湿实验验证

**T7E1 assay**
一种检测"有没有被剪"的经典方法：剪切产生的错配 DNA 会被 T7E1 酶切开，跑胶能看到两条带。灵敏度约 1–5%。
*项目里*：`docs/设计方案.md` §8 的最低验证套餐第一步。

**amplicon 深度测序（amplicon NGS）**
把目标位点 PCR 出来做高通量测序，直接数 indel 比例。比 T7E1 定量、灵敏。

**indel**
插入/缺失突变。ZFN 切开后细胞修复时产生的"疤痕"，是"真的切了"的证据。

**ZFN-Site / Tagger**
一个在线工具（`epd.expasy.org/tagger/`），在已有基因组里搜 ZFN 位点和脱靶。本方案的脱靶算法语义参照它，但**没有**实现其完整打分矩阵。
*项目里*：建议用它交叉核对本地的 in silico 结果。

## 7. 软件与工程术语

**流水线（pipeline）**
按固定顺序跑的一串步骤。本方案 7 步：`ingest → targetscan → designability → build → score → report → fusion`。

**骨架移植（backbone swap）**
保留已知结构的骨架，只替换识别螺旋。本方案用它生成蛋白序列。

**占位符（placeholder）**
序列里出现 `[FOKI_CD:user_supplied]` 这种方括号，表示**这个元件没有可靠序列**，不能直接合成。
*项目里*：`fusion.is_complete` 为 `False` 时一定会出现。

**真值断言（ground truth assertion）**
拿一个"必须成立"的事实当测试。本项目的例子：把 1AAY 的三条真实螺旋填回模板，必须**逐字节还原** 90 aa 的天然序列。

**种子库（seed library）**
一小份**可复核**的手写数据（本项目 3 条，全来自 PDB 1AAY），作用是"证明骨架正确"、给测试当真值锚点，不是"够用"。
*对照*：真正供设计用的是 `data/finger_library_b1h.csv`（1,027 条，来自 B1H 实验数据）。

**库覆盖缺口（coverage gap）**
指头库里"缺某个三联体"或"缺某个位置的数据"。**不是错误，是事实**：报告会把缺口列出来，并给出"该补哪些三联体"的清单。

**重复序列（repeats / RepeatMasker）**
基因组里反复出现的段落（Alu、LINE、SINE、卫星、rRNA 基因簇……）。同一段序列在基因组里有几十到几十万个近似拷贝，**落在这里的位点没有位点特异性**：看着是一个靶点，实际上到处都能结合。
*项目里*：`--repeats` 读 RepeatMasker 的 `.out`/`.bed`，落在注释区间里的窗口**不产出候选**（`genome.IntervalIndex`）。

**多拷贝候选（multi_copy）**
扫描过程中**同一段 18–25 bp 序列第二次出现**的候选。重复注释只覆盖"已知"重复，`multi_copy` 兜住注释漏掉的拷贝：这类候选在报告里单独标出、**不参与设计**。
*为什么重要*：不能当单靶点的位点，做出来就是个到处乱切的酶。

**全基因组扫描（genome scan）**
不把序列读进内存，而是流式分块扫整个 FASTA（`zfn_design/genome.py`）。人类基因组 3.1 Gbp、三指、spacer 5/6/7、双链 ≈ 186 亿个窗口，纯 Python 全量枚举不现实——**正确用法是先用 `--regions` 缩小到启动子/外显子**，再叠加 `--repeats` 与 `--limit`。

## 8. 容易混淆的三组词

| 容易混 | 区别 |
|---|---|
| **结合 vs 切割** | 蛋白"摸住"DNA ≠ 真的把它剪断。染色质、甲基化、FokI 几何都会插在中间。本方案只算结合相似度。 |
| **三联体 vs 半位点** | 三联体 = 3 bp（一个指头）；半位点 = 9 bp（三个指头）。 |
| **指位 F1/F2/F3 vs 三联体顺序** | 写半位点是从 5'→3'，数指头是从 N→C，两者**方向相反**。`GCGTGGGCG` 的 F1 是最后三位 `GCG`，不是前三位。这条错了后面全错。 |
